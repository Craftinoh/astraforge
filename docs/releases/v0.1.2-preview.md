# AstraForge v0.1.2-preview: texture decoding and memory diagnostics

**Source-only pre-release.** This snapshot is for contributors and local investigation. Rendering, memory use and frame pacing still have serious limitations.

## Changes since v0.1.1-preview

- Corrected a one-word offset in BCPack BC7 dictionary indices. The decoder matches local reference streams byte for byte for BC1, BC3, BC4, BC5, BC6H and BC7; the visual effect of this specific correction has not been isolated in play.
- Placed textures within an existing block in the free range that leaves the least space behind. `VICTORY_POOL_BEST_FIT=0` restores the earlier placement. This changes placement, not the amount of card memory allocated.
- Added counters for texture-block fullness and cache syncs with level-2 writeback, and logging for the per-quad sample mask. The sample mask is logged but not applied. Copy-back is not yet gated on writeback.
- Added an opt-in 120-second hang-watchdog limit to the RTX 3070 profile. Large `XMemAllocDefault` allocations now log their memory type; `VICTORY_WC_XMEMALLOC=1` additionally treats eligible types as write-combined and remains off in the supplied profile.
- Kept the write-combined copy-back threshold at 64 KiB. The free-piece texture path is off by default after a measured paging regression. The render-target reserve remains at its prior default.
- The build helper now removes earlier managed artifact directories after a successful new build and manifest. This cleanup has passed a PowerShell parse check; no new build has exercised it yet.

## Exploratory measurements on one RTX 3070 8 GB / 32 GiB host

Each row is a 120-second PresentMon capture of frames classified as `Application`, after the automated route reached a high-draw scene. The two Release runs used the same clean binary. These are individual diagnostic sessions, not the repeated 600-second gameplay benchmark required for the 30 fps target.

| Run | Application frames | Average fps | Median fps | 1% low fps |
|---|---:|---:|---:|---:|
| Release 1 | 960 | 8.05 | 25.84 | 1.08 |
| Release 2 | 2,380 | 19.87 | 27.34 | 3.32 |
| Diagnostic, best fit on | 2,381 | 19.87 | 24.81 | 5.88 |
| Diagnostic, best fit off | 2,296 | 19.19 | 24.56 | 4.79 |

The Release runs peaked at 19.08 and 19.28 GiB of process-private memory. Available commit fell to 3.31 and 3.54 GiB. System-wide NVIDIA telemetry peaked at 7,271 and 7,069 MiB of 8,192 MiB VRAM; it includes other processes. In the diagnostic base run, the texture queue reported no room in 28 of 34 samples, with 596 textures waiting at the end and 826 MB free in pieces inside the texture blocks. These single runs do not establish a gain from best-fit placement.

The operator saw a mostly correct early scene followed by slow or black textures. An experimental combined run with `VICTORY_WC_BAR=1` and 1 MiB windows showed alternating bright and black frames and was stopped; those switches were not added to the profile. The separate `VICTORY_WC_XMEMALLOC=1` run was not reached. No 30 fps target, visual fix, or 16 GiB RAM compatibility is claimed.

## Build and distribution

- The measured local binaries came from clean source commit `3861c90`, build ID `20261128-120547-Both-thinlto-b2c1b72c`, with Rust 1.98.1, MSVC, ThinLTO and portable x86-64 settings. The release tag adds documentation and build-tool changes; imported renderer source is unchanged from the measured commit.
- No binary is attached: a privacy scan found a compile-time personal source path in both local executables despite Rust source-path remapping. Build locally with `tools/Build-AstraForge.ps1` and scan executables before redistribution.

Use only your own legally obtained application files outside the repository. Public reports use anonymous scene labels. This release contains no private application files, caches, saves, or captures. GPL-3.0 and upstream notices remain in force; patch provenance is recorded in `docs/source-credits.md` and `third_party/nvidia-3070-VI/LOCAL-CHANGES.md`.
