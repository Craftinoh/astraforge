# AstraForge v0.1.0-preview — first visible output on RTX 3070

**Pre-release.** This is an early diagnostic preview for contributors and testers, not a
finished or benchmarked build. Use it to reproduce, measure, and report.

## What works (observed 2026-11-27 on one RTX 3070 8 GB / Ryzen 7 7700X / 32 GiB PC)

- The tested Series S title now shows its start-up screens, account selection,
  first-boot menus, and story loading art. Before this release the whole output was black.
- With a warmed shader cache and pipeline library, story load reaches the world and the
  session keeps running without an exception. In one run of a few minutes, the world
  drew 2,500–3,800 draws per frame.

## Main fixes in this release

- **Black output:** reverted local commit `f8b6af5`. It moved the shader descriptor
  clamp below the per-draw dynamic descriptors, so every dynamic table read null. Found
  by bisection with frame captures.
- **Crash on story load:** static-sampler pipelines were kept out of the pipeline library
  on NVIDIA and rebuilt on every launch (201 s of driver time in one run). The title's
  own watchdog then ended the run after more than 30 s without a frame. The RTX 3070
  profile now sets `VICTORY_LIBRARY_STATIC_SAMPLERS=1`.
- Three shader-translation corrections ported from Vice-Tay PR #229, plus the Vice-Tay
  `fa8fc1d` static-sampler library switch. Credits are in `docs/source-credits.md`.

## Known limits (read before testing)

- **Textures stream in slowly, and colours/materials are largely missing.** Some
  characters render black and there is heavy flickering. Leading hypothesis, not yet
  tested: `VICTORY_TEXTURE_NO_WAIT=1` in the baseline profile combined with one-shot
  texture bakes.
- **Performance is low, even in in-game settings menus.** That points to a per-frame
  CPU-side cost (streaming or synchronization) rather than scene complexity; not yet
  diagnosed. The internal window caption showed roughly 4–15 frames/s.
  That caption is **not** a validated FPS measurement. No PresentMon capture exists for
  this release, and no FPS figure is claimed.
- The first launch after a new build (or a new cache) still rebuilds pipelines and may
  hit the title's watchdog on story load. Launch again: the library is saved during the
  run, and the next launch loads it.
- `VICTORY_LIBRARY_STATIC_SAMPLERS=1` may restore a pipeline with the wrong sampler
  (wrong texture filter). The proper fix is a sampler table, which is not ported yet.
- **High CPU load.** In a settings menu with 9 draws per frame, the process used about
  104 ms user + 35 ms kernel CPU time per frame across all threads, while the GPU was
  nearly idle. The log attributes about 95 ms per frame to list-call translation by
  worker threads (`VICTORY_THIN=1`, baseline profile). This is the first optimization
  target. It is not fixed in this release.
- Black characters: the log shows that the decoration bake runs without first uploading
  the textures it samples (`VICTORY_BAKE_TEXTURES_MS=0`). This is a lead, not yet
  tested.
- Only NVIDIA Ampere (RTX 3070) was tested. AMD and other GPUs are not supported.
- The Release binary was built from the same source as the diagnostic build tested in
  game; the Release binary itself has not yet been run in game.

Run `tools/Start-AstraForge3070.ps1` with your own legally owned game files, then follow
`docs/benchmark-procedure.md`. Report GPU, driver, profile, what you saw, and logs, with
private paths and titles removed. Use anonymous scene labels such as `scene-01`. No game
files are distributed here or accepted in reports.
